# Owner protocols and invariant tests

These protocols are normative additions to the exact [target command signatures](target-command-contracts.md), existing source validation and [implementation decisions](implementation-decisions.md). Each accepted-intent fact includes OperationProvenance and a verified immutable intent/content reference. All transitions use owner-local OCC. Public requests cannot manufacture trusted proofs. Tests use the existing xUnit fixtures and `Should<Behavior>Given<Condition>` convention; arrange competing appends explicitly rather than depending on sleeps.

## Signed assertion claims and duty-scope designation

`FirmProfessionalDutyDesignation` owns the active assertion for one canonical user/duty/scope; `ProfessionalAssertionIdentityClaim` binds one assertionId permanently. Verify signature, issuer, subject, exact tenant scope, duty, validity interval, authority revision and active staff proof before accepting immutable designation intent. Use the signed assertionId as the retry identity for both designation and revocation; DesignationId identifies the designation, not a repeated assertion refresh. Claim assertionId before applying. A different digest/subject under that assertion is Conflict. For recording, authorize exact active canonical staff use before assertion claim and hold through native designation; revocation does not require active staff. Rejection fences delayed apply before settling staff use. Application must supersede exactly the current assertion/revision; continuity is broken by any real revocation or inactive interval. Preserve the current rules for professional independence and ratification. Do not release a used signed assertion claim. Recover an accepted, valid-at-admission assertion forward after transient failure without treating a newer unrelated signed assertion as its retry.

Tests: unrelated duties/scopes do not contend; two designation IDs for the same duty scope serialize; changed signed assertion with same assertionId conflicts; higher authority revision supersedes only exact prior assertion; revoked assertion cannot be reactivated by replay; stale/expired/wrong-tenant signature never appends; crash after claim recovers exactly once.
