# Target reactors and typed receivers

Selected target effects replacing or supplementing [24 current reactors](reactor-contract-catalog.md). JSON names every exact required field, concrete proof union, named resolved intent, receiver guard and emitted native fact. All receivers are trusted internal commands with no HTTP/MCP surface. Intent references the named [durable record](durable-intent-schemas.md); process-stage labels are not native event types.

Every receiver belongs to at least one [ordered process](#ordered-processes); the process record that dispatched it owns its position. Derive logical CommandId from source event, effect kind, canonical target and lifecycle episode; preserve RootOperationId/CausationEventId. Attempt identity differs. Persist a recoverable CAS process before advancing the source checkpoint; source replay creates missing process records. Never assume domain append/process CAS atomicity. Exact replay appends nothing, superseded no-op requires proof, unavailable authority stays pending, changed intent or invalid proof conflicts/quarantines. Nullable ExpectedRevision never means replace the original expected token with current state.

## Ordered processes

A reactor row is a receiver contract, not an independent worker. The `processes` array in the JSON companion is normative: each process is one durable CAS record per root source fact, and it dispatches its receivers in the stage order below. Within an acquire, reserve or claim stage the record acquires every key from the frozen manifest in canonical unsigned UTF8 stream-key order, never in the order receivers are listed. Implementing one receiver of an ordered process without its process record is a defect. Abort commands (from [source admission](source-admission-contracts.md)) fence the receiving operation before any settlement stage runs.
