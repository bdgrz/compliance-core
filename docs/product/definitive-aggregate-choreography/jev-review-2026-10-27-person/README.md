# Person focused replay review

The definitive catalog assigns one person per tenant and caller-provided PersonId. The person owns revisioned contact values and its current platform-user correlation; Member owns membership authority. Keep these fields together as the current state of one revisioned person, rather than splitting the source-backed owner. The owner holds a bounded header and immutable-content reference; historical facts and content remain external. Concurrent changes contend on the same person revision because both mutate that current record. Portia supplies stream hydration and persistence.

`PersonRules.CorrelateMembership` changes the correlation, revision, actor and time, but does not revise contact values. Native replay previously accepted a changed contact-values hash in a correlation fact. The malformed-history regression demonstrates that hydration accepted it; the replay guard now requires the preceding values hash. Creation, revision, correlation, no-op and retry retain their existing contracts. This does not validate membership eligibility, which belongs to its own authority.

Jev 1.14.0 answered 0.87 that the stated invariant requires rejecting a correlation that changes contact values. Its boundary answer was 0.39 and is inconclusive. The exact request and response are retained here; the catalog and code, not that score, establish the selected boundary.
