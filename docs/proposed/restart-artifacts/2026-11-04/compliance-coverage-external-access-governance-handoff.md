Critical body rules

- Populations: current owner has draft/accepted only, no discarded lifecycle. Target Open has same-instance accepted supersedes reference, manual-attestation-only source, future-time refusal and instance version; only the supported parts are proved by existing Open/Accept handlers. Remove-row-file, discard and explicit supersession commands/events are absent.
- Persistent delegation: campaign launch permits a nonowner reviewer with authored DelegationReason (LaunchAccessReviewCampaignHandler.cs:238-242; AccessReviewCampaignTests.cs:269), which is not a durable instance delegation plus active membership check on each use.
- Frozen campaign routing: AccessReviewCampaignTests.cs:111 proves frozen populations/reviewers/instructions/deadline; :293/313/330 proves owner program/remediation-owner/current access requirements. Reassignment exists but requires eligibility loss; target general launched remediation-owner change and no reviewer/remediation-owner overlap need explicit acceptance.
- Frozen item identity/classification/effective paths: launch fan-out materializes derived item IDs and stored snapshots. Self-review/privileged guards are concrete in AccessReviewRules.cs:69-96. Current self-review is SubjectUserId-based; target human/shared-account person/accountable-person semantics must remain source-verified after moving classifications.
- Decision vocabulary is currently keep/modify/revoke/unable_to_determine; target keep/remove/change. Treat transport/event cutover explicitly, not as approved behavior merely from existing names.
- Exceptions are checked with future dates but target specific approval/request/revoke rules are absent. Nullable legacy remediation expiry is also accepted by CheckException's current comparison; target expiry is required.
- Effective source authority/tenant privacy: restricted-population/campaign tests assert no visibility from wrong grant, tenant, or source; accepted operation tests bind exact intent/actor and replay. These strong existing checks should be preserved, not counted as target outcome choreography.
- Coverage: AccessReviewCoverageTests.cs:53/84 and :159/226/254 prove broad scans and foreign source refusal. Target campaign-level missing exception and later-in-scope uncovered gap remain distinct gaps; current generic exception records cannot be credited as target campaign exception approvals.
- Control occurrence citation of campaign remains cross-context; no target occurrence citation was established in this audit. Work queue should project gaps, not create automatic remediation.
- API/DI currently expose legacy open/record/accept, classify, propose/approve/exempt, launch/decision/bulk/completion and remediation surfaces. Target delegation, persistent classification/reconfirm, exception request/review/revoke, row-file remove/discard, item close/refusal outcome, batch answer and campaign outcome routes/contracts/JSON/event catalogs require coordinator wiring.

Ready small capabilities: verified-item decision edit refusal; durable instance delegation/acceptance authority; one exception request/review kind. Larger dependency sequence: instance classification -> target frozen item -> close/refusal outcome -> campaign completion ledger, with bulk per-item answers separate. Existing legacy process crash tests are transferable evidence, not target completion.
